# Forge Stack Context — P19 Validation

CLAUDE.md — Context briefing for AI assistants working in this repository.

## What this repo is
The validation layer: the James Checklist's method, as part of the stack,
with a deterministic engine (`validate_v0_1.py`) that scores a run as the
checklist page does. SPEC.md and PROPOSAL.md.

## The rules here (non-negotiable)
1. **R9: nothing private goes in this repo.** James's rules, guard words,
   constraints and runs live in `~/.forge/validation/` only. Never copy
   the page, its old spec or his past runs here. They name his work.
   Before any commit, run the tests: `test_published_files_hold_no_guarded_words`.
2. **One source of truth.** The page's data block is the method.
   `method_v2_2.json` is generated by `tools/extract_v0_1.py`; never edit
   it by hand.
3. **The engine is a port; parity decides.** Change the engine only to
   match the page. Run `tests/test_parity_v0_1.py` on the laptop, where
   the page is. A new rule on the page means a new version of the method
   and the engine.
4. **Advice, not a gate (0.1.0).** A run never blocks a build. Whether it
   ever does is James's decision, after 3 recorded runs.
5. **An AI's answers are assumptions.** A run drafted by an AI says so,
   leaves the outside check and the red team to James, and has no
   verdict until he gives one.

Never rewrite a primitive. Add a layer.
